6. Поиск вещей

Поиск должен выполняться одновременно:

по названию;

по описанию.

Можно использовать @Query.

Пример JPQL:

@Query("select i from Item i " +
"where upper(i.name) like upper(concat('%', ?1, '%')) " +
"or upper(i.description) like upper(concat('%', ?1, '%'))")
List<Item> search(String text);

Это JPQL, а не обычный SQL: запрос работает с сущностями и полями модели.

Добавьте логические проверки в сервисе. Например, пользователь не должен иметь возможности создать вещь с пустым названием.

7. Модель Booking

Добавьте сущность Booking.

Поля:

id — уникальный идентификатор;

start — дата и время начала;

end — дата и время окончания;

item — вещь;

booker — пользователь, выполняющий бронирование;

status — статус.

Статусы

WAITING
APPROVED
REJECTED
CANCELED

Значения:

WAITING — новое бронирование, ожидающее одобрения;

APPROVED — подтверждено владельцем;

REJECTED — отклонено владельцем;

CANCELED — отменено создателем.

8. Функция бронирования

8.1. Создание

POST /bookings

Создать запрос может любой пользователь.

После создания:

status = WAITING

8.2. Подтверждение или отклонение

PATCH /bookings/{bookingId}?approved={approved}

approved принимает:

true
false

Изменить статус может только владелец вещи.

Результат:

true  -> APPROVED
false -> REJECTED

8.3. Получение бронирования

GET /bookings/{bookingId}

Доступ:

автору бронирования;

владельцу вещи.

Ответ должен содержать статус бронирования.

8.4. Бронирования текущего пользователя

GET /bookings?state={state}

По умолчанию:

ALL

Допустимые значения:

ALL
CURRENT
PAST
FUTURE
WAITING
REJECTED

Назначение:

ALL — все;

CURRENT — текущие;

PAST — завершённые;

FUTURE — будущие;

WAITING — ожидающие подтверждения;

REJECTED — отклонённые.

Результат сортируется по дате от более новых к более старым.

Для state рекомендуется отдельное перечисление DTO/слоя представления, поскольку его задачи отличаются от статуса Booking.

8.5. Бронирования вещей владельца

GET /bookings/owner?state={state}

Возвращает бронирования для всех вещей текущего пользователя.

Параметр state работает аналогично предыдущему эндпоинту.

Для бронирований можно использовать:

LocalDateTime end,
Sort sort
);

Не обязательно создавать @OneToMany между Item и Booking.

Можно хранить ссылку:

Booking -> Item

и получать бронирования дополнительным запросом через BookingRepository.
